# hvrkinesisagent.py - HVR AWS Kinesis and S3 Connector

An **HVR agent script** that integrates with **AWS Kinesis** and optionally **Amazon S3**.  
It processes JSON data files generated by HVR and transmits them to a Kinesis stream and/or S3 bucket.  

---

## 📖 Synopsis

```bash
# As an agent
python hvrkinesisagent.py <mode> <loc> <chn>
```

- `mode`: Execution mode (`refr_write_end`, `integ_end`, or `refr_write_begin`)  
- `loc`, `chn`: Ignored in this implementation  

---

## ⚙️ Description

- Reads JSON files supplied by HVR (through `HVR_FILE_LOC`)  
- Each JSON entry is treated as a **Kinesis message** or **S3 object entry**  
- Supports **retries with exponential backoff** when sending to Kinesis  
- Enriches each message with **HVR metadata**, CDC details, and additional headers  
- Removes processed files from the filesystem  

---

## 🚀 Modes

- **`refr_write_end`**  
  Send data files to Kinesis and/or S3, then drop staging tables.  

- **`integ_end`**  
  Same as `refr_write_end`: send data and drop staging tables.  

- **`refr_write_begin`**  
  Clean up the staging file location before refresh.  

---

## 🌍 Environment Variables

The script requires several user arguments provided by HVR’s agent plugin framework.

### Required
- `HVR_FILE_LOC` – Location of JSON files to be processed  
- `HVR_TBL_NAMES` – Colon-separated list of HVR table names  
- `HVR_BASE_NAMES` – Colon-separated list of HVR target base table names  
- `HVR_FILE_NAMES` – List of files transferred into filesystem (if empty → no integration) 

## 🌍 User Arguments

The script requires several user arguments provided by HVR’s agent plugin framework.

### Required
- `AWS_REGION` – AWS region where Kinesis/S3 resources exist  
- `KINESIS_STREAM` – Kinesis stream name (can use `{hvr_tbl_name}` for per-table streams)

### Optional
- `KINESIS_PARTITION_KEY` – Column(s) for partition key (default: primary key columns)  
- `KINESIS_TRACE` – Enable verbose tracing if non-zero  
- `S3_ENABLED` – Enable S3 output (default `0`)

---

## 🔑 AWS Credentials

This script uses **boto3** to interact with AWS. Credentials must be configured as per [boto3 documentation](https://boto3.amazonaws.com/v1/documentation/api/latest/guide/credentials.html), for example using:

- `~/.aws/credentials`  
- IAM roles (if running in EC2/ECS/EKS)  
- AWS Secrets Manager (retrieved dynamically in the script)  

---

## 🗂️ Additional Metadata

Extra metadata fields can be added to JSON messages if included in HVR’s column properties:

- `op_type` → maps to `hvr_op_`  
- `op_timestamp` → maps to `hvr_cap_timestamp`  

---

## 🧪 Diagnostics

- Tracing can be enabled with `HVR_KINESIS_TRACE=1`  
- The script logs retries, partition keys, and unexpected file patterns  
- Successfully processed files are removed after transmission  

---

## 📦 Dependencies

- Python 3.6+  
- boto3  
- botocore  

Install via pip:

```bash
pip install boto3 botocore
```

---

## 📌 Notes

- Supports **retries with exponential backoff + jitter** for Kinesis failures  
- Uses **Secrets Manager** to retrieve AWS access keys dynamically  
- Files are removed only after successful transmission

## ⚙️ Channel Action
### AgentPlugin
To integrate this script into an HVR channel, add a **Channel Action** of type `AgentPlugin` with the following configuration:

```bash
Command=/home/fivetran/hvr_config/plugin/agent/hvrkinesisagent.py
UserArgument="{ 'aws_region': 'eu-west-3',
                'kinesis_stream': 'customersv2-chk-y2-ame-kda',
                'max_retries': 10,
                'base_delay': 0.7,
                'batch_size': 50,
                'kinesis_endpoint_url': 'https://vpce-xxxxxxxxx.kinesis.eu-west-3.vpce.amazonaws.com',
                'plaque': 'LZ2',
                's3_enabled': 0,
                'kinesis_trace': 0,
                'environment': 'chk',
                'alias': 'RCT-HRS-SQL-USHOP',
                'server': 'USHOPWCSQLHRS51',
                'instance': 'DEFAULT',
                'base': 'AMERICASRCT_Y2' }"
ExecOnHub
```

### Integrate
```bash
RenameExpression="{hvr_chn_name}-{hvr_cap_tstamp %s}-{hvr_integ_tstamp}-000-{hvr_tbl_name}.json"
MaxFileSize=400000
```

This ensures the HVR agent executes the script with the required configuration when running in the hub.
